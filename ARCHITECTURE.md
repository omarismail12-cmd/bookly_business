# Bookly Business — Architecture Document

Generated by a full read-only scan of the codebase. Covers every folder under `lib/` and `supabase/`, every file under `lib/core/`, `lib/app/`, and `lib/features/*/`, every migration in `supabase/migrations/`, every RPC/function defined across those migrations, the app boot sequence, and the full routing table. A consolidated "Notes for the developer" section at the end lists everything flagged as dead code, inconsistent, or technical debt.

Stack: Flutter + Riverpod (state/DI) + go_router (routing) + Supabase (Postgres/Auth/Storage/Realtime/Edge Functions) as the backend, with an offline-first local mirror (SQLite on native, `localStorage` on web) and a write-sync queue for a handful of entities.

## 2. File-by-file documentation

### 2.1 `lib/core/`

#### `analytics/`

**`crash_reporting.dart`** — `abstract interface class CrashReporting` with `initialize()`, `recordError(Object, StackTrace, {String? reason})`, `setUser(String? userId)`. Pure contract.

**`firebase_crash_reporting.dart`** — Implements `CrashReporting` via Firebase Crashlytics, exposed as a module-level singleton `crashReporting`. `initialize()` no-ops on web; on other platforms tries `Firebase.initializeApp()` in try/catch — on success wires `FlutterError.onError` to Crashlytics and sets `_available = true`; on failure logs and stays a permanent safe no-op. `recordError`/`setUser` early-return if unavailable, otherwise forward to Crashlytics, each independently try/catch-guarded.

#### `config/`

**`app_config.dart`** — `AppConfig` static class: `supabaseUrl`/`supabaseAnonKey` from `String.fromEnvironment` (must be passed via `--dart-define`), `appName = 'Bookly Business'`, `isConfigured` (true only if both URL/key are non-empty) — used by `main.dart` to decide whether to boot the real app.

**`supabase_provider.dart`** — `supabaseProvider`, a Riverpod `Provider<SupabaseClient>` returning `Supabase.instance.client`.

#### `errors/`

**`app_exception.dart`** — `AppError implements Exception` (`message`, optional `cause`). Unused anywhere else (dead code).

**`failure.dart`** — completely empty file (0 bytes).

#### `local/` (offline read-mirror storage, native/web split)

**`local_store.dart`** — `abstract interface class LocalStore`: `put(table, id, data)`, `get(table, id)`, `list(table)`, `delete(table, id)` — a generic JSON-blob key/value store keyed by `(table, id)`.

**`local_store_factory.dart`** — conditional export selecting `local_store_web.dart` or `local_store_native.dart` via `dart.library.io`.

**`local_store_native.dart`** — factory returning `SqliteLocalStore()`.

**`local_store_web.dart`** — factory returning `InMemoryLocalStore()` (name is a misnomer — see Notes).

**`local_store_provider.dart`** — `localStoreProvider`, Riverpod `Provider<LocalStore>` wrapping `createLocalStore()`.

**`in_memory_local_store.dart`** — web-only; despite the class name, backed by `window.localStorage` (key prefix `bookly_local_store_v1_`), one JSON blob per table. `put` adds a `_cached_at` timestamp; `list` sorts descending by it; all storage-quota/private-browsing failures are swallowed in try/catch. No Supabase calls.

**`sqlite_local_store.dart`** — `SqliteLocalStore implements LocalStore`, backed directly by the `sqlite3` package (not Drift — a comment explains Drift's codegen is unresolvable under this project's pinned Dart SDK). Single generic table `local_store(table_name, id, data JSON, updated_at)`; `put` is an upsert (`ON CONFLICT ... DO UPDATE`). No Supabase calls.

**`app_database.dart`** — `AppDatabase` singleton; `open()` lazily opens/creates a SQLite file at `<app documents dir>/bookly_business_local.sqlite`, creating `local_store` and `sync_queue` tables on first open. Native-only (guarded by `kIsWeb` at call sites).

#### `localization/`

**`local_provider.dart`** — `AppLocaleController extends ChangeNotifier` (locale state + `setLocale`). Unused anywhere else (dead code) — `app.dart` resolves locale purely via `MaterialApp.router`'s `localeResolutionCallback`.

**`gen/app_localizations*.dart`** — standard `flutter gen-l10n` generated output from `lib/l10n/app_en.arb`/`app_ar.arb`. Not hand-edited.

#### `notifications/`

**`notification_service.dart`** — `abstract interface class NotificationService`: `initialize()`, `requestPermission()`, `subscribeToOrganization(id)`, `unsubscribeFromOrganization(id)`.

**`firebase_notification_service.dart`** — `FirebaseNotificationService implements NotificationService`, instantiated directly (not via Riverpod) in `business_shell.dart`. Same safe-no-op pattern as crash reporting. `subscribeToOrganization`: gets an FCM token, **Supabase call** `from('device_tokens').upsert({organization_id, user_id, token, platform}, onConflict: 'token')`, then re-saves on `FirebaseMessaging.instance.onTokenRefresh`. `unsubscribeFromOrganization`: **Supabase call** `from('device_tokens').delete().eq('organization_id', id).eq('user_id', uid)`.

#### `pdf/`

**`pdf_service.dart`** — `abstract interface class PdfService`: `createReceipt(data)`, `createReport(data)`, both returning raw PDF bytes.

**`pdf_document_service.dart`** — `PdfDocumentService implements PdfService` using the pure-Dart `pdf` package (fully offline, no external service). Instantiated directly at call sites (`payments_page.dart`, `reports_page.dart`), not via Riverpod. `createReceipt`: A5 page with business name/reference/date/customer/method/type/amount. `createReport`: A4 page with a stat-tile `Wrap` (occupancy/appointments/completed/no-shows/revenue) and, if present, a per-staff performance table. No Supabase calls.

#### `permissions/`

**`app_role.dart`** — `enum AppRole { owner, manager, receptionist, staff, customer }` + extension with `canManageSettings`, `canTakePayments`, `canViewReports` convenience getters. Doc comment: `owner/manager/receptionist/staff` come from `organization_members.role`; `customer` is the customer-portal counterpart scoped by `customers.profile_id = auth.uid()` RLS.

**`permission.dart`** — `enum Permission { viewDashboard, manageCalendar, manageQueue, manageCustomers, manageServices, manageStaff, takePayments, viewReports, manageCrm, manageSettings }` + `PermissionX.allowedFor(AppRole)` — returns `false` immediately for `AppRole.customer`, then per-permission role checks.

#### `security/`

**`org_context.dart`** — `OrganizationMembership` data class (`organizationId`, `organizationName`, `timezone`, `currency`, `role`). Top-level `fetchActiveMembership()`: **Supabase call** `from('organization_members').select('organization_id,role,organizations(id,name,timezone,currency,status)').eq('user_id', uid).eq('status', 'active').limit(1)`; returns null if the joined org isn't `active`. Riverpod `FutureProvider`s chained off it: `activeMembershipProvider`, `activeOrganizationProvider`, `activeRoleProvider`, `activeCurrencyProvider` (defaults `'USD'`). The single source of truth for "what org/role is the current user," consumed across nearly every feature.

#### `sync/` (offline write queue)

**`sync_models.dart`** — `SyncOperation`: `operationId`, `entity`, `entityId`, `operation`, `payload`, mutable `retryCount`/`status`/`detail`.

**`sync_queue_store.dart`** — `abstract interface class SyncQueueStore`: `enqueue`, `pending()`, `markSynced`, `markFailed`, `pendingCount`/`failedCount`, `resetFailed`, `markConflict`, `conflicted()`, `conflictCount`, `resolveKeepMine`, `resolveKeepTheirs`.

**`sync_queue_store_factory.dart` / `_native.dart` / `_web.dart`** — same native/web conditional-export pattern as `local_store`.

**`in_memory_sync_queue_store.dart`** — web-only, backed by `localStorage` key `bookly_sync_queue_v1` (same "InMemory" naming inconsistency as `in_memory_local_store.dart`). Implements dedupe-by-id enqueue, status filtering, retry counting (flips to `'failed'` at 5 retries), conflict tracking.

**`sqlite_sync_queue_store.dart`** — `SqliteSyncQueueStore implements SyncQueueStore`, backed by the `sync_queue` SQLite table from `app_database.dart`. No direct Supabase calls — Supabase writes happen in `sync_service.dart`.

**`sync_service.dart`** — `syncServiceProvider` builds `SyncService(Supabase.instance.client, createSyncQueueStore())`. Holds `ValueNotifier<int>` for pending/failed/conflict counts (drives `SyncStatusBanner`), and a `Connectivity().onConnectivityChanged` subscription that calls `drain()` on reconnect. `drain()` iterates pending ops and switches on `op.operation`:
  - `'create_customer'` → **Supabase call** `from('customers').upsert(payload)`.
  - `'update_customer'` → legacy path, `from('customers').update(payload).eq('id', entityId)`, no version check (dead-producer path, see Notes).
  - `'update_customer_notes'` → `_applyVersionedUpdate` against `customers`, fields `private_notes`/`next_recommendation`.
  - `'update_service_description'` → `_applyVersionedUpdate` against `services`, field `description`.
  - `'upsert_working_hours'` → `from('working_hours').upsert(..., onConflict: 'staff_id,weekday')`.
  - `'upsert_staff_break'` → `from('staff_breaks').upsert(..., onConflict: 'staff_id,weekday')`.
  - unknown kind → dropped as synced.
  `_applyVersionedUpdate`: unless `payload['_force']`, fetches the current row and compares `version` against `_base_version`; on mismatch calls `store.markConflict(...)` and throws internally, otherwise performs the update. Also exposes `conflicts()`, `resolveConflictKeepMine/Theirs`, `retryFailed()`.

**`workspace_mirror.dart`** — `WorkspaceMirror`: read-only local-first mirror of `['appointments','queue_entries','customers','services','staff']`. `refresh(organizationId)` runs 5 independent Supabase selects over a 16-day appointments window (and full/limited selects for the others), each writing results into `LocalStore` via `store.put`, with per-table failure isolation. `cached(table, organizationId)` reads back from `LocalStore` filtered client-side. `workspaceMirrorProvider` exists but is never watched anywhere (see Notes — `business_shell.dart` constructs its own separate instance).

#### `theme/`

**`app_theme.dart`** — `AppTheme.light()` — the app's only theme (no dark mode). Material 3, seed color `#8B5CF6`, `GoogleFonts.inter()` with Arabic fallback (`notoSansArabic`), themed AppBar/Card/Input/FilledButton/NavigationBar.

### 2.2 `lib/app/`

**`main.dart`** — Entry point. `runZonedGuarded` wraps: `WidgetsFlutterBinding.ensureInitialized()` → `crashReporting.initialize()` → if `!AppConfig.isConfigured`, `runApp(ProviderScope(child: ConfigMissingApp()))` and return early (no Supabase init attempted) → else `Supabase.initialize(url:, publishableKey:)` → `runApp(ProviderScope(child: BooklyApp()))`. No provider overrides passed in either branch. The zone error handler calls `crashReporting.recordError(...)` for any uncaught error. `ConfigMissingApp` is a minimal fallback screen shown only when Supabase env vars are missing.

**`app.dart`** — `BooklyApp` builds `MaterialApp.router`: title `'Bookly Business'`, `theme: AppTheme.light()` only (no dark theme/themeMode), `supportedLocales`/`localizationsDelegates` from generated `AppLocalizations`, `localeResolutionCallback` matches device language against supported locales (no user-facing switcher), `routerConfig: appRouter`. No other top-level listeners/overrides.

**`router.dart`** — see §6 below (full route table + redirect logic).

### 2.3 `lib/shared/`

**`formatters/currency.dart`** — `formatMinor(int minor, {String currency = "USD"})`, formats minor-unit integers as currency via `intl`'s `NumberFormat.currency`. Used across ~10 files.

**`validators/validators.dart`** — `Validators` static class, locale-aware (`AppLocalizations l10n` param): `email` (required + regex), `password` (required + min 8 chars), `confirmPassword` (required + equality), `name` (required + min 2 chars after trim).

**`widgets/async_state.dart`** — `AsyncErrorView({error, onRetry})` and `EmptyState({message})`. Hardcoded English strings, not localized (inconsistent with `Validators` in the same folder — see Notes).

**`widgets/skeleton.dart`** — `SkeletonBox` (animated shimmer primitive, no external package), `SkeletonCard`, `SkeletonList`, `SkeletonStatCard`, `SkeletonStatRow` — the app's standard loading-placeholder family, used across 13 files.

**`widgets/sync_status_banner.dart`** — `SyncStatusBanner` (ConsumerStatefulWidget), the visible UI for `SyncService` state. Tracks connectivity locally; watches `syncServiceProvider`'s three `ValueListenableBuilder`s (pending/failed/conflict counts); renders nothing when fully synced and online, otherwise a priority-ordered banner: conflicts ("Resolve") > failed ("Retry") > offline > syncing ("Retry now"). `_openConflicts` shows an `AlertDialog` listing each `SyncOperation` via `_ConflictTile`, with "Keep theirs"/"Keep mine" actions. Used at the top of both `BusinessShell` and `CustomerShell`.

### 2.4 `lib/features/auth/`

**`data/auth_service.dart`** — `AuthService(SupabaseClient)`: `signUp`, `signIn` (→ `signInWithPassword`), `signOut`, `currentUser` getter. **Entirely unused** — no provider, never instantiated (see Notes).

**`presentation/login_page.dart`** — Business login screen. Fields: email (`Validators.email`), password (obscured, `Validators.password`, visibility toggle). Primary button "Sign in" (`l10n.loginSubmit`, spinner while loading); text button "No account?" → pushes `SignupPage`. `_login()` calls `Supabase.instance.client.auth.signInWithPassword(...)` **directly** (bypassing `AuthService`), with mapped error messages for invalid credentials / unconfirmed email.

**`presentation/signup_page.dart`** — Business signup screen. Fields: full name, email, password, confirm password (all validated). Primary button "Sign up"; text button "Have an account?" → pop. `_signUp()` calls `auth.signUp(...)` directly with `data: {'full_name': ...}`; if no session returned (email confirmation required), shows a blocking "Check your email" dialog before popping.

### 2.5 `lib/features/organisations/`

**`data/organization_repository.dart`** — `OrganizationRepository(SupabaseClient)`: `myOrganizations()` (joined select of `organization_members`+`organizations`), `create(name, slug, timezone)` (→ `rpc('create_organization_for_current_user')`). **Entirely unused** — presentation code duplicates this logic with direct RPC calls instead (see Notes).

**`presentation/business_shell.dart`** — `BusinessShell`, the main authenticated shell for business roles. `load()`: `rpc('get_my_memberships')` (determines suspension) + `fetchActiveMembership()`; on success registers for push (best-effort, try/catch-wrapped), sets crash-reporting user id, refreshes its own separately-constructed `WorkspaceMirror`. States: loading spinner; suspended (message + "Sign out"); no membership (renders `OrganizationSetupPage`); membership present → role-filtered navigation to 12 destination pages (Staff Today [staff only], Dashboard, Calendar, Queue [not staff], Customers, Services [owner/manager], Locations [owner/manager], Staff [owner/manager], Payments [owner/manager/receptionist], CRM [owner/manager], Offers [owner/manager], Reports [owner/manager]) — wide layout uses `NavigationRail`, mobile uses a 4-item `NavigationBar` + "More" bottom-sheet for overflow items. AppBar shows org name, role, and a logout icon button.

**`presentation/organization_setup_page.dart`** — Shown when the user has no active org membership. Fields: Business name, Slug, Timezone (prefilled `'Asia/Beirut'`). Buttons: "Create business" (→ `rpc('create_organization_for_current_user')`, validates name length and slug regex `^[a-z0-9-]{3,40}$`), "Create demo business + test data" (→ `rpc('seed_demo_data_for_current_user')`), "Sign out" (AppBar action).

### 2.6 `lib/features/staff/`

**`data/staff_repository.dart`** — `StaffRepository(client, localStore)`, `staffRepositoryProvider`.
- `listActive(orgId)` — `from('staff').select().eq('organization_id',o).isFilter('deleted_at',null).order('display_name')`; falls back to cached local rows on failure.
- `listIdNameActive(orgId)` — lightweight `id,display_name` projection filtered to `status='active'`; same offline fallback.
- `create({organizationId, displayName})` — `from('staff').insert({...})`.
- `softDelete(id)` — `from('staff').update({deleted_at: now}).eq('id', id)`.
- `assignRoleByEmail({organizationId, email, role})` — `rpc('set_member_role_by_email', {p_org, p_email, p_role})`.
- `linkToUserByEmail({staffId, email})` — `rpc('link_staff_to_user_by_email', {p_staff, p_email})`.

**`data/staff_schedule_repository.dart`** — `StaffScheduleRepository(client, syncService)`, `staffScheduleRepositoryProvider`. Wraps `working_hours`, `staff_breaks`, `blocked_times`.
- `workingHours(staffId)` — `from('working_hours').select().eq('staff_id',id)`.
- `upsertWorkingHours(...)` — **local-first**: enqueues `SyncOperation('upsert_working_hours')` and drains — no direct Supabase call here.
- `deleteWorkingHours(id)` — `from('working_hours').delete().eq('id', id)`.
- `staffBreaks(staffId)` / `upsertBreak` (local-first, same pattern) / `deleteBreak(id)`.
- `blockedTimes(staffId)` — `from('blocked_times').select().eq('staff_id',id).order('starts_at')`.
- `addBlockedTime({staffId, startsAt, endsAt, reason})` — `from('blocked_times').insert({...})`.
- `deleteBlockedTime(id)` — `from('blocked_times').delete().eq('id', id)`.

**`domain/staff_member.dart`** — `StaffMember` mirrors `public.staff`: `id`, `organizationId`, `profileId` (nullable), `displayName` (default `'Unnamed'`), `status` (default `'active'`), `createdAt`/`updatedAt`, `createdBy`/`updatedBy`, `deletedAt` (nullable), `version` (int, used for optimistic-concurrency checks). Read-only model (`fromRow` only).

**`domain/staff_schedule.dart`** — Three models: `WorkingHours` (mirrors `public.working_hours`: `id`, `staffId`, `weekday` 0–6, `startTime`/`endTime` as raw `"HH:MM:SS"` strings); `StaffBreak` (identical shape, mirrors `public.staff_breaks`); `BlockedTime` (mirrors `public.blocked_times`: `id`, `staffId`, `startsAt`/`endsAt`, `reason?`, `createdAt`).

**`presentation/staff_page.dart`** — Staff directory. Header "Assign role" button (owner only) → dialog: email field + role dropdown (Manager/Receptionist/Staff) → `assignRoleByEmail`. Per-row: link-login icon button (owner only) → dialog: account email field → `linkToUserByEmail`; "Schedule" icon button (owner/manager) → pushes `StaffSchedulePage`. FAB "Add staff" (owner only) → dialog: display-name field → `create`.

**`presentation/staff_schedule_page.dart`** — 3-tab schedule editor ("Working hours" / "Breaks" / "Blocked time") for one staff member. Tabs 1–2: 7 weekday rows, tap opens a start/end time-picker dialog with Remove/Cancel/Save. Tab 3: list of blocked-time entries with delete icon buttons; FAB "Add" (visible only on this tab) opens the shared blocked-time dialog.

**`presentation/blocked_time_dialog.dart`** — `showAddBlockedTimeDialog(...)`, shared between `StaffSchedulePage` (owner/manager) and `StaffTodayPage` (staff self-service). Date/start-time/end-time pickers + optional reason field; validates start < end; → `addBlockedTime`.

### 2.7 `lib/features/staff_portal/` (presentation only)

**`presentation/staff_today_page.dart`** — Staff member's own "Today" view (default landing tab for `AppRole.staff`). Resolves own `staffId` via `from('staff').select('id').eq('organization_id',o).eq('profile_id',uid).maybeSingle()`, then queries today's appointments joined with customer/service info. Per-row primary action button advances status: pending/confirmed→"Check in", checked_in→"Start service", in_service→"Complete" (→ `rpc('change_appointment_status')`). AppBar action: "Add blocked time" icon button → shared blocked-time dialog. Tapping a card opens `StaffAppointmentDetailPage`.

**`presentation/staff_appointment_detail_page.dart`** — Read-only customer info (phone/email) plus two editable fields: "Private notes" and "Next recommendation." `save()` enqueues a `SyncOperation('update_customer_notes')` (shared operation name with `customer_detail_dialog.dart`) with optimistic-concurrency `_base_version`; shows distinct snackbars for conflict / offline-pending / success.

### 2.8 `lib/features/customer_portal/` (presentation only)

**`presentation/customer_login_page.dart`** — Customer-facing login (deliberately separate screen from business login, same Supabase Auth backend). Email/password fields, "Sign in" button → `auth.signInWithPassword`, on success `context.go('/customer')`.

**`presentation/customer_signup_page.dart`** — Customer signup: name/email/password/confirm fields → `auth.signUp(..., data: {'full_name': ...})`; on success (with session) `context.go('/customer')`, otherwise a snackbar + pop (no blocking dialog, unlike the business signup screen).

**`presentation/customer_shell.dart`** — Customer app shell, 4-tab `NavigationBar` (no role gating — a customer isn't an org member): "My appointments" (`MyAppointmentsPage`), "Find & book" (`FindBusinessPage`), "Loyalty" (`CustomerLoyaltyPage`), "My offers" (`CustomerOffersPage`). AppBar logout action. `SyncStatusBanner` above the body.

**`presentation/customer_loyalty_page.dart`** — Loyalty points/packages/memberships across every business the customer has a record with. Three read-only list sections from `loyalty_accounts`, `customer_packages` (active), `customer_memberships` (active).

**`presentation/customer_offers_page.dart`** — Active coupons + campaign messages targeted at the customer, across every business. Two sections: "Offers for you" (from `campaign_recipients`) and "Active coupons" (from `coupons`).

## 5. App boot sequence (`main.dart` / `app.dart`)

1. `main()` wraps everything in `runZonedGuarded`.
2. `WidgetsFlutterBinding.ensureInitialized()`.
3. `crashReporting.initialize()` (Firebase Crashlytics singleton — safe no-op if Firebase isn't configured for the platform).
4. If `!AppConfig.isConfigured` (missing `SUPABASE_URL`/`SUPABASE_ANON_KEY` `--dart-define` values): `runApp(ProviderScope(child: ConfigMissingApp()))` and return — **no Supabase initialization is attempted** in this branch.
5. Otherwise: `Supabase.initialize(url: AppConfig.supabaseUrl, publishableKey: AppConfig.supabaseAnonKey)`.
6. `runApp(ProviderScope(child: BooklyApp()))`. **No provider overrides** are passed to `ProviderScope` in either branch — all Riverpod providers use their real implementations from the very first frame.
7. The `runZonedGuarded` error handler forwards any uncaught async/zone error to `crashReporting.recordError(...)`.

`BooklyApp` (`app.dart`) builds `MaterialApp.router` with: `theme: AppTheme.light()` only (no dark theme/`themeMode`), `supportedLocales`/`localizationsDelegates` from the generated `AppLocalizations`, a `localeResolutionCallback` matching the device's language against supported locales (no in-app language switcher), and `routerConfig: appRouter`. No other top-level listeners or overrides.

## 6. `lib/app/router.dart` — full routing table

Uses `go_router`. `appRouter = GoRouter(initialLocation: '/login', refreshListenable: GoRouterRefreshStream(Supabase auth state changes), redirect: ..., routes: [...], errorBuilder: ...)`.

**Auth guard (`redirect`, evaluated on every navigation and on every Supabase auth state change):**

- `loggedIn = auth.currentSession != null`; `businessAuth` = `/login`/`/signup`; `customerAuth` = `/customer/login`/`/customer/signup`; `customerRoute` = any path starting `/customer`; `publicBooking` = any path starting `/book/`.
- **Not logged in:** navigating into `/customer/...` (not a customer-auth page) → redirect to `/customer/login`. Otherwise, if not on a business-auth, customer-auth, or public-booking page → redirect to `/login`. Else no redirect.
- **Logged in:** on `/login`/`/signup` → redirect to `/home`. On `/customer/login`/`/customer/signup` → redirect to `/customer`. Else no redirect.
- **Gap:** the guard only checks "is there any session," not whether that session belongs to a business member vs. a customer profile — a signed-in customer hitting `/home` directly (or a signed-in business user hitting `/customer`) is not redirected by this logic alone.

**Route table:**

| Path | Widget | Notes |
|---|---|---|
| `/login` | `LoginPage()` | Business login |
| `/signup` | `SignupPage()` | Business signup |
| `/home` | `BusinessShell()` | Main authenticated business app shell |
| `/customer/login` | `CustomerLoginPage()` | Customer-portal login |
| `/customer/signup` | `CustomerSignupPage()` | Customer-portal signup |
| `/customer` | `CustomerShell()` | Main authenticated customer-portal shell |
| `/book/:slug` | `BookingPage(publicSlug: slug)` | Public booking page for one organization, reachable without auth |
| `/book` | `BookingPage()` | Public booking page with no slug pre-selected |

No route declares a `name:` parameter — all in-app navigation is path-based (`context.go('/path')`). There is no `ShellRoute`; the tab/section switching inside `BusinessShell`/`CustomerShell` is internal widget state, not nested go_router routes — so deep-linking to a specific tab isn't possible with the current table.

`errorBuilder`: renders a "This page could not be found." screen with a "Go home" button (`context.go('/home')`) for any unmatched route.

`GoRouterRefreshStream extends ChangeNotifier`: generic adapter wrapping Supabase's `auth.onAuthStateChange` broadcast stream, calling `notifyListeners()` on every event so go_router re-evaluates `redirect` whenever the user signs in/out.

## 7. Notes for the developer (dead code, inconsistencies, technical debt)

### Dead code

1. **`lib/features/auth/data/auth_service.dart`** — `AuthService` (`signUp`/`signIn`/`signOut`/`currentUser`) has no Riverpod provider and is never instantiated. `login_page.dart`/`signup_page.dart` call `Supabase.instance.client.auth.*` directly instead. Fully dead.
2. **`lib/features/organisations/data/organization_repository.dart`** — `OrganizationRepository` (`myOrganizations`, `create`) is never instantiated. `business_shell.dart`/`organization_setup_page.dart` duplicate its logic with direct `rpc(...)` calls. Interestingly, `staff_repository.dart`'s doc comment claims to mirror "OrganizationRepository's style" even though that repository itself is unused.
3. **`lib/core/errors/app_exception.dart`** — `AppError` class, never referenced anywhere.
4. **`lib/core/errors/failure.dart`** — completely empty file (0 bytes).
5. **`lib/core/localization/local_provider.dart`** — `AppLocaleController`, never instantiated or wired to any UI; locale resolution goes entirely through `MaterialApp.router`'s `localeResolutionCallback` instead.
6. **`lib/features/services/data/services_repository.dart`** — `softDelete(id)` is defined but never called; `services_page.dart` has no delete/deactivate UI at all. Either dead code or a missing feature.
7. **`lib/core/sync/sync_service.dart`** (`'update_customer'` case in `drain()`) — explicitly a legacy no-conflict-check path; no current call site enqueues this operation name anymore (superseded by `'update_customer_notes'`). Kept only to drain any already-queued ops from an older app version.
8. **`lib/core/sync/workspace_mirror.dart`** — `workspaceMirrorProvider` is registered but never watched; `business_shell.dart` instead constructs its own separate `WorkspaceMirror` instance directly, bypassing the provider entirely. Two parallel, disconnected instantiation paths for the same class.

### Structural / architectural inconsistencies

9. **`lib/features/appointments/`** has no `data/`/`domain/` subfolders at all — `booking_page.dart`/`calendar_page.dart` call `Supabase.instance.client` directly and pass raw `Map<String, dynamic>` rows, unlike every sibling feature (queue, services, packages, payments), which wrap Supabase access in a `*Repository` + typed domain model. The most significant pattern deviation in the codebase.
10. **`lib/features/customers/`, `dashboard/`, `locations/`** have no `data/`/`domain/` layering either — raw maps in widget state, no repository/model classes — unlike `reports/`, which has a clean split. `customers/` additionally has two independent, duplicated implementations of the same customer-list feature (`customers_page.dart` and `loyalty/crm_page.dart`), with different query logic, different dialog field orders, and different offline-durability guarantees for customer creation (`customers_page.dart` goes through `SyncService`; `crm_page.dart` writes directly).
11. **`lib/features/organisations/presentation/business_shell.dart` / `organization_setup_page.dart`** call `Supabase.instance.client.rpc(...)` directly rather than going through a repository, unlike `staff/` (which has `StaffRepository`/`StaffScheduleRepository`).
12. **Inconsistent DI patterns across `core/`**: `CrashReporting` is a module-level singleton; `NotificationService`/`PdfService` implementations are instantiated directly at feature call sites; `sync`/`local` layer classes are exposed via Riverpod `Provider`s. Three different wiring styles for structurally similar "platform adapter" classes.
13. **Inconsistent error handling across sibling list pages**: `locations_page.dart` surfaces fetch errors via a visible `AsyncErrorView` + retry; `customers_page.dart` silently falls back to the cached local store with no error UI; `crm_page.dart` has no try/catch at all in `load()`, so a failed request is silently swallowed by Flutter's zone handling and `loading` stays `true` forever.
14. **Inconsistent currency formatting**: `services_page.dart` and `customers_page.dart` both render money as raw `value / 100` instead of the shared `formatMinor(..., currency:)` helper used everywhere else (calendar, payments, offers, CRM, reports, dashboard) — ignores the organization's actual currency and locale formatting.
15. **Inconsistent numeric-field handling**: `services_page.dart`'s "Add service" dialog omits `keyboardType: TextInputType.number` on numeric fields (unlike `offers_page.dart`/`payments_page.dart`) and uses uncaught `int.parse` for Duration/Buffer instead of `int.tryParse`.
16. **`lib/features/packages/data/packages_repository.dart`** has no update/deactivate/delete methods for packages, memberships, or coupons (create/list only), and unlike `queue_repository.dart`/`services_repository.dart` has no offline local-store fallback.
17. **Duplicated RPC call**: `customer_detail_dialog.dart`'s `redeemCoupon()` calls `rpc('redeem_coupon', ...)` inline instead of using `PaymentsRepository.redeemCoupon`, which wraps the identical call — same RPC, two independent call sites.
18. **Naming collisions/misnomers**: `in_memory_local_store.dart`/`in_memory_sync_queue_store.dart` are actually backed by `localStorage` (persisted), not truly in-memory, despite the class names — though each file's own doc comment correctly explains the real behavior. `packages/domain/package_offer.dart`'s `Membership` (a purchasable discount plan) shares its name with the unrelated org-`activeMembershipProvider` concept used elsewhere.
19. **`lib/app/router.dart`** — no `name:` on any route; no `ShellRoute` for `BusinessShell`/`CustomerShell` despite both being tab-shell UIs, so deep-linking to a specific tab isn't possible. The auth `redirect` guard checks only "is there a session," not business-vs-customer identity (see §6).
20. **`lib/core/theme/app_theme.dart`** — only a light theme exists; `app.dart` sets no `themeMode`, so there's no path to dark mode without further wiring.
21. **`lib/shared/widgets/async_state.dart`** — `AsyncErrorView`/`EmptyState` use hardcoded English strings, not routed through `AppLocalizations`, unlike `Validators` in the same `shared/` folder.

### Stale comments

23. **`lib/core/sync/sync_queue_store.dart`** and **`lib/core/local/local_store.dart`** — both doc comments describe a planned "Drift-backed" implementation; the actual native implementation uses raw `sqlite3` calls (Drift's codegen is explicitly noted elsewhere as unresolvable under this project's pinned Dart SDK).

### Product/UX gaps worth confirming intent on

26. **`lib/features/customer_portal/presentation/my_appointments_page.dart`** — appointment rows have no `onTap`; customers can't drill into appointment detail from this screen (unlike business-side staff/queue lists).
27. **`lib/features/staff/presentation/staff_page.dart`** — "Assign role" and "Link login" are gated to `role == 'owner'` only, while "Schedule" is gated to owner-or-manager — an asymmetry worth double-checking against product intent.

### Supabase migration history worth knowing about (see §3 for full detail)

30. **0007 → 0014**: a broken `ON CONFLICT` clause in `queue_appointment_notifications()` silently rolled back **every booking** made through the real app between 0007 and 0014 being applied — the most significant historical bug in the migration history.
31. **0008 → 0009**: `reverse_payment()` referenced a column (`payments.notes`) that never existed, crashing refunds at runtime until 0009.
32. **0015 → 0016**: the first attempt to lock down function EXECUTE grants didn't work because Supabase grants `anon`/`authenticated` EXECUTE directly at function-creation time, not via the `PUBLIC` pseudo-role that 0015 revoked from.
33. **0017 → 0019**: 0017's "fix" for record-not-found crashes in `cancel_appointment`/`reschedule_appointment` was itself incomplete — the real bug was a RECORD variable colliding in name with a SQL table alias (both named `a`), fixed for real only in 0019.
34. **0031 → 0032**: `link_staff_to_user_by_email()` didn't account for `set_member_role_by_email()` already auto-creating a duplicate staff row, causing a unique-constraint collision; 0032 fully replaces 0031's function body.
35. **`notification_jobs.kind`** has grown ad hoc across five migrations (`confirmation`, `reminder_24h`, `reminder_2h`, `campaign`, `confirmation_staff`, `reschedule`, `reschedule_staff`) as free-text string literals with no CHECK constraint enforcing the allowed set, unlike `appointments.status`/`payments.type` which do have CHECK constraints.
36. **`set_member_role_by_email()` in migration 0007** is defined twice within the same file (redefined immediately after its first definition to add staff auto-creation) — the first definition is dead code that never survives past that single migration file executing.

No `TODO`/`FIXME`/`XXX` comments and no commented-out code blocks were found anywhere across `lib/core/`, `lib/app/`, `lib/shared/`, or any `lib/features/*/` directory (verified via grep in every research pass).
